Pengantar Normalisasi & Simulator 3 Anomali Data (Before vs After)

Normalisasi adalah teknik perancangan basis data secara bottom-up (berada di antara tahap konseptual dan logikal) untuk menghasilkan himpunan relasi/tabel yang bebas dari redundansi dan anomali data (Insert, Update, dan Delete Anomaly).

Logical → PhysicalRelation → Table
Logical → PhysicalUnique ID → Primary Key
Logical → PhysicalAttribute → Column
Logical → PhysicalTuple → Row

SBD08 • Slide 7 – 14

Bentuk Normal Pertama (1NF): Menghilangkan Atribut Multivalue & Berulang

Suatu relasi berada dalam 1NF jika setiap sel bernilai tunggal (atomic value), tidak ada atribut berulang (seperti use1, use2, use3 atau ID_Pengarang1, ID_Pengarang2), dan telah ditentukan Primary Key / Identifier-nya.

SBD08 • Slide 15 – 25

Functional Dependency (X → Y) & Bentuk Normal Kedua (2NF: Buang Partial Dependency)

Ketergantungan fungsional X → Y berlaku jika untuk setiap dua tuple ∀(t₁.X = t₂.X) ⇒ (t₁.Y = t₂.Y) (nilai X menentukan secara unik nilai Y). Suatu tabel 1NF berada dalam 2NF jika semua atribut non-kunci bergantung penuh (Fully Functional Dependency) pada seluruh Composite Primary Key, bukan hanya menumpang pada salah satu subset kunci (Partial Dependency).

SBD08 • Slide 26 – 33

Bentuk Normal Ketiga (3NF): Membuang Transitive Dependencies

A (PK) → B (Non-Key) → C (Non-Key)

Suatu relasi berada dalam 3NF jika sudah 2NF dan tidak ada atribut non-kunci yang bergantung pada atribut non-kunci lainnya (A → B dan B → C di mana B ↛ A dan B bukan identifier).
